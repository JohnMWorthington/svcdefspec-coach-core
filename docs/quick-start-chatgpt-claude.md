Service Definition & Specification Coach
CORE Quick Start — ChatGPT and Claude — v0.1.26


Use this when you simply want to use the Coach.


1. Download the public CORE package
Use the official public repository:
https://github.com/JohnMWorthington/svcdefspec-coach-core


2. Start a new conversation
Use a new ChatGPT or Claude chat for a clean case.


3. Upload
Upload:
- core/svcdefspec-core.md
- your service evidence


Evidence can be an SLA, agreement, service description, catalog, spreadsheet, supplier data, workshop notes, or other relevant material.


4. Start with this prompt


Use the uploaded Service Definition & Specification Coach CORE as your operating method for this conversation. Apply it to the service evidence I provide. Keep the method outside-in, preserve Current/Future/Open distinctions, and follow its phase gates.


Review this material and help me understand the service it describes. Start with the current state and ask only the few questions that materially improve the definition.


5. Phase 1
The Coach should help you understand the Current service before redesigning it.


Expect:
- Customer/Provider boundary;
- Useful Completion;
- Facility and Support;
- Functionality and Functioning;
- Map and Canvas;
- evidence/inference/conflicts/Open items;
- only a few material questions.


6. Phase 2
When Current is coherent, tell the Coach to move to operational detail.


Expect a small representative set of customer-to-provider interactions.


Do not expect detailed routing, RACI, workflow, approval chains, procedures, or CMDB/MIR design.


7. Phase 3
When ready to formalize, ask it to move to formalization.


It should begin with the USM Alignment & Gap Review before rewriting the agreement.


8. Watch for these controls
The Coach should not:
- turn every team/tool/supplier into a service;
- silently turn Future into Current;
- resolve conflicts by assumption;
- invent commitments;
- treat supplier uptime as proof that users can work;
- treat ticket closure as proof of recovery;
- drift into detailed workflow design.


9. ChatGPT
A normal new ChatGPT chat with file upload is enough for CORE.


10. Claude
A normal Claude chat is enough for CORE.
A Claude Project is not required.
On Free, larger cases may require a usage reset; continue in the same chat afterward.


11. FULL
You do not need FULL for normal use.


FULL is available upon request for approved professional/organizational use when you need controlled canon, enhanced execution assets, peer-review/assurance material, or governed MCP/API integration.


12. Human responsibility
Review important outputs before using them for commitments, contracts, governance, or organizational decisions.
